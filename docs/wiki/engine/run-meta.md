# Run & meta (engine internals)

*Page anatomy + durability rules: [[README|engine hub]]. The roguelike-structure concept companion is [[roguelike-meta]]; the reward-screen splice/clone mechanics live in [[synthesis-staple]], the opponent-scaling mechanics in [[draft]]. This page carries the verified mechanics of `run.js` and `picklog.js`: the slot model, the save/migration lifecycle, the mid-game snapshot revert, reward generation, the endless map, run modifiers, and the picklog analytics layer.*

## What it does

The run layer is everything that outlives a single game: the run deck (the **slots array**), the localStorage save with its versioned migration chain (`load`/`save`/`MIGRATIONS`), the mid-game-quit snapshot revert (`midGameSlotsSnapshot` / `rollbackForMidGameRestore`), the win-reward machinery (`generateRewardOffer` → `rollOneCandidate` → `pickRewardCandidate`), result recording (`recordResult`), the sector map (`generateMap`), the seven run-start boons (`RUN_MODIFIERS`), and a fire-and-forget pick-analytics sidecar (`PICKLOG.logPick` / `finishDraft`) that no gameplay code reads.

## The flow

- **The slot model is the run's spine.** The slots array *is* the run deck; every in-game card caches its run-slot index as `slotIdx` at deck build. That cache creates a documented invariant class: `removeSlotByIdx` carries a written **caller contract** — anyone removing a slot must decrement the cached `slotIdx` of every in-game card sitting past the removed index. The honoring sites are `ripSlotForPhylactery`, `ripSlotByIdx` (side-aware, does both halves), and both splice fixups. A **second index set the contract does not name** — `playedSlotIdxs`, the per-game record of which slots were actually played, feeding the win-reward filters via `recordResult` — is remapped by the removal sites that maintain the cached `slotIdx`. Insertion discipline is clean: `appendSlot`-style writes go at end/after-self only, so the stale-pointer class is **fully enumerated** and one shared fixup helper closes all of it.
- **The save lifecycle and the migration-authoring lesson.** Saves carry a `SAVE_VERSION`; `load` runs `MIGRATIONS` entries upward while the blob's version is behind, then applies a sticker-only normalization pass — nothing else repairs shape. The durable lesson: **a migration must be written against the git-verified real historical shape, never a remembered or guessed one.** The v1→v2 tplId-rename migration must cover the three real v1 tplId carriers (`midGameSlotsSnapshot`, `pendingReward.replacementPack` in both shapes, `modifier`); a migration that targets fields no persisted save ever carried — with a unit test that pins that phantom shape — stays green while doing nothing, leaving the un-migrated snapshot to resurrect dead tplIds so the next deck build throws "Unknown card" and the catch wipes the save: a test worse than absent. The real v1 shape is recoverable from git (`df2fd38^`), which is what a correct migration pins against. Companion discipline, same family: **every extension of a rename table needs a version bump** — a snake_case rename sweep that extends TPLID_RENAMES without bumping SAVE_VERSION leaves a window of v2 saves no migration ever touches. The migration loop is upward-only: a future-version blob passes through without a guard.
- **The mid-game snapshot revert (anti-farming, by design).** At game start the run takes `midGameSlotsSnapshot`, a full copy of the slots array; quitting mid-battle and resuming triggers `rollbackForMidGameRestore`, which restores the snapshot — you cannot farm mid-game rewards/slot changes by quitting. The revert is **complete for run-state**: the only thing outside its scope is picklog's games-played counter (analytics-only).
- **Rewards: pre-rolled at offer, persisted — the one designed randomness discipline.** `generateRewardOffer` rolls every candidate (`rollOneCandidate`) at *offer* time and persists the offer in the save; `pickRewardCandidate` only commits a pre-rolled choice. Reloading therefore re-presents the identical offer — **no reload-scum vector exists anywhere in the run layer** (everything is pre-rolled+persisted or committed-in-pick). The reward-type distribution `REWARD_TYPE_WEIGHTS` matches canon [[1504-rewards|§1504]] exactly. The guard *strength* across the four pick handlers is asymmetric (sticker/ripUp trust the pre-roll; twoStickers/transform re-validate) — benign because nothing mutates slots between offer and pick. `recordResult` persists the game outcome plus `lastPlayedSlotIdxs`, the played-slots filter the sticker rewards aim at (the consumer of the `playedSlotIdxs` index).
- **The endless sector structure.** `generateMap` builds one sector's node map; clearing the sector generates a fresh map and the run continues — **the run ends only in a loss**. Every map exit is a boss. Opponent difficulty scales with cumulative game number under the **/1 /3 /5** divisors (stickers / staples / clones, matching canon §1503); the scaling mechanics themselves are [[draft]]'s territory. Canon §1500 documents this endless structure and the reward wordings to match the code.
- **The seven RUN_MODIFIERS.** Run-start boons, all seven traced end-to-end: every one returns *extras* (cards appended to the deck) — none mutates slots in place. The adopted contract is **mutation-allowed**, matching what the call site tolerates (the boon may either append extras or mutate slots in place); canon §1505 and the code comment document the same seven boons.
- **Picklog is fire-and-forget analytics.** `PICKLOG.logPick` records draft picks (it receives the pre-mutation pack), `finishDraft` seals the record; double `finishDraft` no-ops and a malformed blob catch-resets — idempotent by inspection. No gameplay code reads it. Its one sharp edge is durable: picklog **re-applies TPLID_RENAMES unconditionally on every load**, so the rename table's ~250 legacy keys must never be reused as live card ids — a future card reusing one would have its picklog rows silently rewritten forever. The invariant holds (key-set ∩ live cards = ∅); a cheap assertion is the natural guard against a future reuse.

## Design rulings

In-code deliberate designs, confirmed as design rather than defect: the **mid-game snapshot revert** is intentionally anti-farming and intentionally complete for run-state; **pre-rolled persisted rewards** are the deliberate anti-reload-scum discipline; and the **endless sector structure** (the run ends only in a loss) is the code's intent, with the rulebook documenting it to match. A governing terminology ruling applies across the engine: Magiclike's rules are **the** rules.

## Verified clean

Checked and explicitly cleared: **REWARD_TYPE_WEIGHTS = §1504 exactly** (table-vs-canon diff clean); **opponent scaling matches §1503** (/1 /3 /5); **STICKER_ID_RENAMES values all exist** in the live sticker registry; **TPLID_RENAMES keys ∩ live cards = ∅** (the rename-key-reuse invariant holds); **no reload-scum vector** — everything pre-rolled+persisted or committed-in-pick; **non-stackable sticker dedup holds** through the 2×/3× reward loops; **midGameSlotsSnapshot revert complete for run-state** (only the picklog counter sits outside its scope); **map integrity** — every node has ≥1 in-edge, every non-final node ≥1 out-edge; the legacy multi-successor warn-path is unreachable (back-compat only); **no-reward-on-win is impossible** with ≥1 slot; **zero AI call sites into RUN**; **slot-array insert discipline** (end/after-self only) means the stale-pointer class is fully enumerated; **picklog idempotency** by inspection. Cross-cutting: `RUN.applySplice` is reward-screen-only — the engine never calls it, so the in-game splice path stays [[synthesis-staple]]'s verified ground.
